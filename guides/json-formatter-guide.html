1. JSON 格式化是什么

JSON（JavaScript Object Notation） 是一种轻量的数据交换格式，常见于 API 响应、前端配置、日志与测试夹具。合法的 JSON 使用双引号键名、有限的值类型（对象、数组、字符串、数字、布尔、null），并且不能包含注释。

格式化（美化） 会在不改变数据含义的前提下，为对象与数组添加缩进和换行，让层级一目了然。 压缩（minify） 则去掉多余空白，减小体积。 校验 会检查文本是否符合 JSON 语法；失败时通常能指出大致位置，便于修错。

WebUtils 的 JSON 格式化工具 把这三件事放在同一页完成，适合调试时快速往返。

2. 什么时候需要做

  • API 调试 ：响应被缩成一行，或混有转义字符，需要展开字段层级。
  • 配置检查 ：提交前确认 package.json、前端配置或 mock 数据无语法错误。
  • 对比前预处理 ：先格式化再 diff，避免空白差异干扰；也可用 JSON Diff 做结构对比。
  • 传输前压缩 ：需要紧凑字符串时，用压缩而不是手删空格。

3. 在线操作步骤

  1. 打开 JSON 格式化工具。
  2. 将 JSON 文本粘贴到输入区（可来自接口、剪贴板或本地文件内容）。
  3. 点击格式化：若语法正确，会得到缩进后的可读结果；若失败，根据提示定位问题。
  4. 需要紧凑输出时，使用压缩；需要复制结果时使用页面提供的复制操作。
  5. 敏感数据请在本地脱敏后再粘贴；工具侧重本地处理，仍建议最小化暴露真实密钥。

若你的数据实际是 YAML，可先用 JSON ↔ YAML 转换 再决定是否继续以 JSON 维护。

4. 常见错误与处理

键名或字符串用了单引号

JSON 要求双引号。把 {'a': 1} 改成 {"a": 1}。

尾逗号（trailing comma）

对象或数组最后一个元素后多写了逗号，例如 {"a": 1,} 。删掉末尾逗号即可。部分 JS 对象字面量允许尾逗号，但标准 JSON 不允许。

多余注释

// 或 /* */ 不是 JSON 的一部分。配置若来自「类 JSON」文件，需先去掉注释再校验。

括号不配对

缺 } / ] 或多重嵌套抄漏一层。格式化失败时从报错位置向上检查最近的开闭符号。

数字与特殊值

不要写 NaN、undefined；应使用数字、字符串或 null。大整数在部分环境会有精度问题，必要时以字符串承载。

6. 常见问题

JSON 格式化和压缩有什么区别？

格式化便于人读和排错；压缩便于传输与存储。合法前提下，二者不改变数据语义。

为什么我的 JSON 总是校验失败？

优先检查双引号、尾逗号、注释和括号。用 格式化工具 看报错位置，通常比通读全文更快。

在线 JSON 工具安全吗？

WebUtils 以浏览器本地处理为主，但仍请避免粘贴生产环境密钥与个人隐私。公共电脑使用后注意清理剪贴板。
