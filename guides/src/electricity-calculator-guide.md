## 核心一句话 {#tldr}

**电费计算 的价值是把易错步骤变成可复查的本地结果；先固定输入与成功标准，再谈速度。**

主工具：[电费计算](/tools/calculator/electricity-calculator)。处理在浏览器本地完成。生产密钥、客户隐私与未发布数据请脱敏后再粘贴。

### 主题要点 {#topic-key}

度=千瓦时。功率(W)×小时/1000=度。阶梯电价分段计价。待机功耗常被忽略。估算值不能替代电表。

## 它解决什么问题 {#concepts}

电费计算 在真实工作中通常落在三类需求：

1. **校对**：确认格式、数值、协议字段是否符合约定。
2. **转换/生成/解析**：在人类可读与机器可用形态之间往返。
3. **排障**：当上下游各执一词时，用同一套本地结果做中立对照。

### 能力边界

| 能做 | 不能自动完成 |

| 对给定输入给出确定性输出 | 替你做最终业务/合规裁决 |
| 快速迭代并复制结果 | 取代完整 IDE、监控或发布流水线 |
| 用错误表缩小怀疑面 | 在坏输入上“猜”出唯一真相 |
| 与相关工具组成小链路 | 提供云端权限与审计日志 |

### 三句契约（动手前写清）

- 输入来自哪里？
- 成功标准是什么（字段、单位、状态、编码）？
- 失败时最小复现是什么？

## 在 WebUtils 上怎么做 {#steps}

1. 打开 [电费计算](/tools/calculator/electricity-calculator)。
2. 准备**最小可复现输入**，去掉噪声与敏感字段。
3. 走主路径：输入 → 计算/转换/生成/解析 → 查看输出。有开关时先默认再逐项改，便于定位变量。
4. 复制前做**往返或交叉验证**（可逆则逆运算；不可逆则对照第二工具或权威样例）。
5. 记录：输入摘要 + 关键选项 + 输出摘要 + 结论。

### 自检样例

- 平凡样例：最短合法输入
- 边界样例：空、超长、Unicode、极值
- 故意非法样例：缺字段、坏语法
- 脱敏生产形样例：结构像真数据

## 常见错误对照 {#errors}

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 与同事结果不一致 | 选项/单位/编码/方言不同 | 对齐选项并交换原始输入 |
| 粘贴后怪异 | 隐藏字符、全角符号、错误换行 | 纯文本清洗 |
| 大输入卡顿 | 主线程压力 | 切片；批量改脚本 |
| 下游仍失败 | 忽略空白、大小写、顺序 | 严格比较或哈希 |
| 报错含糊 | 一次叠多个问题 | 最小样例二分 |
| 安全事件 | 共享环境粘贴真密钥 | 轮换凭证 |
| 细微数值差 | 舍入、时区、版本 | 固定公式说明 |
| 移动端难用 | 小屏限制 | 改用桌面完成关键步骤 |

## 常见问题 {#faq}

### 为什么和别的网站结果不同？
先核对选项、单位、编码与规范版本，再做字节级对比输入。

### 本地工具绝对安全吗？
相对随意上传更可控，但仍可能被扩展、云剪贴板、屏幕分享泄漏。

### 能替代自动化测试吗？
不能。适合探索与排障；回归应进入 CI，样例可沉淀为夹具。

### 能直接上生产吗？
可作为候选，仍需环境评审、权限、回滚方案。

### 手机端如何？
可打开，复杂输入建议桌面完成。

### 如何证明输出未被手改？
保留输入输出文件，必要时哈希，并写明工具路径与选项。

### 一次粘贴多大？
最小可复现优先；超大内容先裁剪。

### 和付费 SaaS 差在哪？
缺组织权限与云端协作；单次本地确定性结果用 WebUtils 足够。

## 操作细节与验收标准 {#ops-detail}
把一次成功的操作定义成可验收条款，而不是“感觉对了”。建议至少写清：输入形态、必填选项、禁止事项、输出字段、失败时的可见信号。例如：空输入应明确提示而不是静默成功；非法格式应指出最早出错位置；成功输出应能被下游系统直接消费或明确需要二次加工。
对团队协作，把上述条款放进内部文档的“工具卡片”里，新人按卡片操作即可复现。若工具页 UI 变更导致步骤失效，优先更新卡片与本指南的步骤节，而不是只在聊天里口头更正。长期积累后，你会得到一组与业务绑定的验收样例，比通用教程更值钱。
