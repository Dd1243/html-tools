## 核心概念 {#concepts}

### 1. 传统 Unix/Linux 文件权限模型

Linux 文件权限分为三个层面：
- **所有者（Owner）**：文件/目录的创建者
- **组（Group）**：与所有者同组的用户
- **其他用户（Others）**：非所有者和非组的用户

每层权限由 3 个字符表示：`rwx`（读、写、执行）

### 2. 符号权限模式（rwx）

`rwx` 是最直观的表示方式：
- **r**：Read（读取）
- **w**：Write（写入/修改）
- **x**：Execute（执行/进入目录）

例如：`rwxr-xr-x` 表示：
- 文件所有者：可读、可写、可执行
- 组用户：可读、可执行（不能写）
- 其他用户：可读、可执行（不能写）

### 3. 数值权限模式（八进制）

数值表示更适合脚本和批量操作：
- 每个权限位对应一个八进制数字
- 标准模式示例：
  - `644`：文件所有者读写，其他用户只读（常见于配置文件）
  - `755`：文件所有者读写执行，组和其它只读执行（常见于可执行脚本）
  - `700`：文件所有者完全控制，仅限自己访问（敏感文件/密钥）

**数值转 rwx 对应表：**

| 数值 | rwx (owner/group/others) |
|------|--------------------------|
| 4    | r-- / r-- / r--         |
| 5    | r-x / r-x / r-x         |
| 6    | rw- / rw- / r--         |
| 7    | rwx / rwx / rwx         |

### 4. 权限位组合

- **读（r）**：能查看文件内容、查看目录列表
- **写（w）**：能修改文件内容、创建/删除目录项
- **执行（x）**：能运行脚本、进入目录、访问文件

**注意**：目录权限特殊，`x` 允许进入，`w` 允许创建/删除文件。

## 常见错误与排查 {#errors}

| 错误现象 | 可能原因 | 正确做法 |
|----------|----------|----------|
| 文件权限被拒绝 | 缺少执行权限 | 确保目录有 x 权限 |
| 脚本无法执行 | 没有执行权限 | 设置为 755 或 700 |
| 文件被其他用户看到 | 权限设置过宽 | 改为 600/700 |
| 权限变化未生效 | 缓存导致 | `chmod` 后重新登录或 `sudo` |
| 组用户被拒绝 | 组权限设置错误 | 检查 `chgrp` 后再 `chmod` |
| 数值模式输入错误 | 八进制数字必须 0-7 | 7=rwx、6=rw-、5=r-x、4=r-- |

**排查顺序**：
1. 确认权限位是否在 0-7 范围内
2. 检查所有者/组/其他权限是否正确设置
3. 验证目录权限（目录需 x 权限才能进入）
4. 执行 `ls -l` 验证实际效果
5. 考虑文件系统缓存

## 常见问题解答 {#faq}

**Q1: 为什么有些文件必须设置 700 权限？**

A: 敏感文件如 API 密钥、数据库密码等，如果被未授权用户读取，可能导致数据泄露。700 权限确保只有所有者能访问。

**Q2: 符号权限和数值权限有什么区别？**

A: 符号权限（rwx）更直观，数值权限（644/755）更适合脚本和批量操作。两种方式最终效果相同。

**Q3: 如何查看当前文件的权限？**

A: 使用 `ls -l filename` 命令，输出格式为 `drwxr-xr-x`（d 表示目录，- 表示文件）。

**Q4: 为什么修改权限后不生效？**

A: 可能存在文件系统缓存。建议：
- 重新登录
- 运行 `sudo chmod`（如果需要）
- 检查 `ls -l` 命令是否实时生效
- 考虑使用 `chmod --reference` 保留其他属性

**Q5: 目录权限和文件权限有什么区别？**

A: 文件权限主要影响读取/写入；目录权限额外影响进入和创建/删除文件。目录必须有执行权限才能访问内部内容。

**Q6: 如何给组用户赋予特定组的权限？**

A: 先使用 `chgrp groupname filename`，再使用 `chmod` 设置组权限（如 `chgrp web group.conf && chmod 640 group.conf`）。

**Q7: 644 和 755 有什么区别？**

A: 644 是普通文件模式（rw-r--r--），适合配置文件；755 是可执行脚本/目录模式（rwxr-xr-x），适合可执行文件和目录。

**Q8: 为什么不推荐使用 777 权限？**

A: 777 权限（rwx）允许所有用户完全控制文件，可能导致安全风险。应尽量使用最小权限原则（如 644、755、600 等）。

### 更详细的权限位解释

**r 读权限**：

**w 写权限**：
- 文件：能修改文件内容

- 文件：能执行脚本、运行程序

### 特殊权限场景

**Sticky Bit (粘滞位)**：
- 在目录上使用 t 位，表示只有文件所有者能删除
- 例如 `drwxrwxrwt` 表示普通组用户不能删除，但所有者可以

**SUID/SGID**：
- 在文件上使用 s 位
- SUID：执行时以文件所有者身份运行
- SGID：执行时以文件所属组身份运行

**ACL 高级权限**：
- Linux 还支持 ACL（Access Control List），允许更细粒度的权限控制
- 使用 `setfacl` 命令设置

### 权限管理的完整流程

1. **创建文件**：
   - `touch file.txt`
   - `chmod 644 file.txt`

2. **创建目录**：
   - `mkdir directory`
   - `chmod 755 directory`

3. **批量修改**：
   - `find . -type f -name "*.txt" -exec chmod 644 {} \;`

4. **递归设置**：
   - `chmod -R 755 directory/`

5. **恢复默认权限**：
   - `chmod 644 file.txt`
   - `chmod 755 directory`

### 常见问题进阶解答

**Q9: 如何给多个文件设置相同权限？**

A: 使用 `chmod` 的递归选项或批量命令：
- `chmod 644 *.txt`
- `chmod -R 755 /path/to/directory`

**Q10: 为什么有时需要使用 sudo chmod？**

A: 只有 root 用户才能修改系统目录或某些特殊文件的权限。普通用户修改自己的文件时不需要 sudo。

**Q11: 如何在 Windows 系统上实现类似 chmod 功能？**

A: 使用 `icacls` 命令：
- `icacls file.txt /grant Everyone:READ`
- `icacls file.txt /grant Everyone:FULL`

**Q12: 权限设置后如何测试？**

A: 使用 `ls -l` 查看权限
使用 `touch file.txt && chmod 644 file.txt && ls -l file.txt`
使用 `echo "test" > file.txt` 测试读写权限

**Q13: 如何处理权限冲突？**

A: 检查 SELinux/AppArmor 策略（Linux 系统）
使用 `ls -lZ` 查看安全上下文
使用 `restorecon` 命令恢复默认安全上下文

**Q14: 如何在 Docker 容器中设置文件权限？**

A: 在 Dockerfile 中设置：
```
RUN chmod 755 /app
USER 1000
```

**Q15: 如何在 Git 仓库中管理文件权限？**

A: Git 会保留文件权限：
- `chmod 644 file.txt`
- `git add file.txt`
- `git commit -m "Set file permissions"`
