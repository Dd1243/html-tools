## 先记住一个判断 {#tldr}

**角度换算只改变表示方式，不改变几何意义；先确认输入单位，再决定输出精度。**

角度单位都以整圆为共同参照：一整圈是 360 度、2π 弧度、400 百分度、1 圈（turn）。工具页把输入归一化后，再按同一参照计算其它单位。它不会替你判断图纸中的“35”究竟是度还是弧度，也不会替你修正测量仪器的系统误差。

## 单位边界：看似相近，使用场景不同 {#units}

| 单位 | 一整圈 | 典型写法 | 更适合的任务 |
| --- | ---: | --- | --- |
| 度（degree） | 360° | `35°` | 设计稿、日常表达、测量标注 |
| 弧度（radian） | `2π` | `0.610865 rad` | 三角函数、物理公式、动画和 API |
| 百分度（gradian） | 400 gon | `38.8889 gon` | 土木测量、全站仪历史数据 |
| 毫弧度（milliradian） | `2000π` mrad | `610.865 mrad` | 光学、瞄准、工程小角度 |
| 角分（arcminute） | 21600′ | `30′` | 经纬度、视场和天文记录 |
| 角秒（arcsecond） | 1296000″ | `12.5″` | 高精度测量、天文、定位 |
| 圈/转（turn） | 1 turn | `0.25 turn` | 旋转动画、电机控制、周期参数 |

弧度的特殊之处在于“弧长等于半径”时角度为 1 rad，因此公式 `s = rθ` 中 θ 必须用弧度。若把 30 直接当作度代入正弦函数，程序通常会返回一个合法数字，却是错误结果。百分度并不是“百分比角度”，它把直角定义为 100 gon，方便测量人员把四个直角分成 400 个单位。

### 常用公式与可逆检查

- `弧度 = 度 × π / 180`
- `度 = 弧度 × 180 / π`
- `百分度 = 度 × 10 / 9`
- `毫弧度 = 弧度 × 1000`
- `角分 = 度 × 60`，`角秒 = 度 × 3600`
- `圈 = 度 / 360`

例如 35° = `35 × π / 180` ≈ `0.6108652382 rad` = `38.88888889 gon`。把结果再转回度，若只保留 2 位小数会回到 35.00°；若要闭合测量网络，就不要过早四舍五入。

## 先定精度，再使用结果 {#precision}

工具显示的是计算结果，不是测量真值。输入 35° 只有两位有效数字时，输出 0.6108652382 并不意味着测量精度提升了。可以把精度拆成三层：

1. **原始数据精度**：仪器或题目给了几位小数，决定可信范围。
2. **计算精度**：中间过程保留足够位数，避免连续转换累积误差。
3. **展示精度**：报告、界面或接口按约定取整，避免读者误以为更精确。

工程计算建议中间值保留双精度，最终输出再按毫米、角秒或接口约定取舍。动画角度常用 0 到 1 的 turn，既便于插值，也不必反复在 0° 与 360° 之间处理回绕。

## WebUtils 工具页怎么操作 {#steps}

1. 打开 [角度单位转换器](/tools/converter/angle-converter.html)，确认页面标题和输入单位下拉框。
2. 在“输入数值”输入框中填入数字，例如 `35`。允许负角，负号表示顺时针或相反方向，具体方向由你的坐标约定决定。
3. 从单位列表选择真实来源：度、弧度、百分度、毫弧度、角分、角秒或圈。不要因为结果“看起来合理”就跳过这一步。
4. 查看结果网格中的其它单位。若做接口联调，点击对应结果卡片复制完整数值，再在接口文档中注明单位。
5. 用一组已知值做反向检查：输入 `180` 度，应得到约 `3.1415926536` 弧度、`200` 百分度和 `0.5` 圈。
6. 需要换算另一组数据时，直接修改数值或选择单位；连续换算前先确认上一次选择没有被当成新输入单位。
7. 报告只需要整数度或 2 位小数时，在粘贴到表格前统一格式化，保留原始结果以便追溯。

页面在浏览器本地计算，适合复制单值或小批量核对。它不读取 GPS、全站仪或 CAD 文件，也不替代批量脚本和坐标系转换。

## 真实输入与输出对照 {#examples}

### 例一：三角函数接口

输入：`30`，单位选“度”。输出弧度约 `0.5235987756`。JavaScript 的 `Math.sin()` 要接收弧度，因此代码中应写成：

```js
const angleDeg = 30;
const angleRad = angleDeg * Math.PI / 180;
const y = Math.sin(angleRad); // 0.5
```

错误做法是 `Math.sin(30)`，它把 30 当成 30 rad，结果并非 0.5。

### 例二：测量记录

输入：`38.88888889`，单位选“百分度”。输出约 `35` 度、`0.6108652382` 弧度。报告可写 `35°00′00″`，但前提是原记录精度真的支持到角秒；不能因为工具给出很多小数就补造精度。

### 例三：旋转动画

输入：`0.125`，单位选“圈”。输出 `45°`、`0.7853981634 rad`。动画系统若用 CSS `rotate(45deg)`，直接使用度；若时间轴参数表示一圈的比例，保留 `0.125 turn` 更直观。

## 错误表：结果没错，输入可能错了 {#errors}

| 现象 | 可能原因 | 修正动作 |
| --- | --- | --- |
| 30 转成弧度后不是 0.5236 | 输入单位仍是弧度或百分度 | 重新检查下拉框，再用 180° 基准值复核 |
| 三角函数结果完全异常 | 把度直接传给只接受弧度的 API | 先转弧度，代码变量名写清 `Rad` |
| 角分结果大得离谱 | 把 30 角分误当 30 度 | 输入时标注 `′`，必要时先除以 60 |
| 负角方向反了 | 坐标系顺逆时针约定不同 | 统一文档约定，不要在转换器外偷偷取绝对值 |
| 结果尾数每次不同 | 展示端四舍五入位数不同 | 固定输出位数，保留未舍入中间值 |
| 百分度被当成百分比 | 误把 gon 当成 0.38 | 记住直角是 100 gon，整圆是 400 gon |
| 角秒转换丢失小数 | 表格单元格被设置为整数 | 先以文本或高精度数值导入 |
| 180° 得到 3.14 就停止 | 过早取两位小数导致闭合误差 | 计算阶段保留更多位，最终再取舍 |
| 输入空白或科学计数法报错 | 页面输入校验或浏览器限制 | 用普通十进制输入，分组处理大数据 |

遇到争议时，先拿 `0°`、`90°`、`180°` 三个锚点测试。它们分别应映射到 0、π/2、π 弧度；锚点都不对时，问题在单位或程序配置，不在小数精度。

## 工作场景：从图纸到代码的交接 {#scenarios}

**前端旋转组件。** 设计师交付 `270°`，组件 API 以 turn 表示。转换为 `0.75 turn`，并在接口类型旁写单位，避免下一位开发者传入 270。

**机器人关节标定。** 控制器以毫弧度记录小角度偏差，测试报告以度呈现。将 `12.5 mrad` 转为约 `0.7162°`，报告同时保留原始 mrad，便于回写控制器。

**地理坐标显示。** 数据库存十进制度，用户界面要显示度分秒。把 `116.397128°` 拆成 `116°23′49.6608″`，注意经度方向、负号和四舍五入进位；坐标格式转换还涉及南北东西，不只是数值换算。

**光学视场。** 规格写 `2.5°`，镜头算法用弧度；换算后代入近轴近似。若角度不够小，不能只靠 `sin θ ≈ θ`，应保留三角函数真实值。

**测量数据审计。** 发现一列“400”为单位不明，先检查仪器说明：它可能是 400 gon 的整圆，也可能是 400° 的异常输入。单位不明的数据不能直接批量转换。

## 边界、安全与数据留痕 {#safety}

- 工具处理的是角度标量，不负责椭球、投影、基准面或坐标系变换；经纬度换算不能替代 GIS 投影转换。
- 极大数值会受到 JavaScript 浮点表示限制；做天文或高精度测量时，应在专业软件中使用高精度库复核。
- 页面本地计算不会上传输入，但共享屏幕、浏览器历史和剪贴板仍可能暴露内部参数。敏感项目用完清空页面和剪贴板。
- 角度换算不涉及权限提升，但错误的单位可能影响机械运动、导航和安全阈值；上线前必须用独立样例验算。
- 文档中记录“数值 + 单位 + 舍入规则 + 来源”，不要只保存一个无单位数字。

## 相关工具如何选 {#related}

### 结果如何写进数据契约

如果角度要在团队之间长期传递，建议把字段写成对象而不是裸数字，例如 `{ "value": 0.6108652382, "unit": "rad" }`，并在接口说明中写明正方向、取值范围和舍入规则。这样前端、后端和测试脚本都能在输入阶段发现单位遗漏。对于可回绕的旋转角，还要说明是允许 `-10°`，还是必须规范到 `[0, 360)`；两种约定在插值和排序时会产生不同结果。数据导出时保留原始测量值与换算值，便于发现“工具换算正确但来源单位写错”的问题。

### 连续换算的审计方法

连续转换时不要把每一步的展示结果当作下一步输入。例如度转弧度后只显示 6 位，再转角秒会放大舍入误差。更稳妥的做法是保存高精度中间值，最后一次性按目标格式取整；同时记录转换链路，例如“测量记录 gon → 内部 rad → 报告 DMS”。当结果用于安全阈值、机械限位或定位时，再用独立计算器或短脚本抽查极端值。

- [角度单位转换器](/tools/converter/angle-converter.html)：单值和小批量的角度单位互转。
- [三角形计算器](/tools/calculator/triangle-calc.html)：已知边角求解几何关系，转换器只负责单位。
- [科学计算器](/tools/calculator/scientific.html)：在弧度模式下继续计算三角函数和公式。

选型顺序是：先确认单位，再用转换器换表示；涉及几何未知量用计算器；涉及批量文件或坐标系，用脚本和专业测量软件。

## 常见问题 {#faq}

### 为什么 1 弧度约等于 57.2958 度？

因为整圆是 `2π` 弧度和 360 度，所以 `1 rad = 180/π°`。57.2958 是展示近似值，公式计算应保留 π 或足够精度。

### 负角能不能直接转换？

可以。转换器会保留符号；但顺时针为正还是逆时针为正取决于你的坐标系。机器人、地图和 CSS 的约定可能不同，不能只看数值。

### 角分、角秒和时间的分秒是一回事吗？

符号相似但语境不同。角分 `′` 和角秒 `″` 是角度单位；时间的分钟、秒钟不是角度，只有在特定天文坐标语境中才会出现对应关系。

### 为什么同一个弧度在表格里显示成 0.61，在代码里是 0.610865？

展示位数不同，不代表数学值不同。表格适合阅读，代码应按误差预算保留更多位；不要把界面四舍五入后的数字当成原始值。

### 百分度适合普通网页动画吗？

通常不适合。动画和浏览器 CSS 更常用度或圈；百分度主要服务测量系统。只有上下游都采用 gon 时，才值得保留该单位。

### 工具能把一批 CSV 角度自动转换吗？

当前页面面向单值交互和核对，不承诺 CSV 批处理。批量任务应先明确列单位，再用脚本读取、转换、校验和输出日志，避免把不同列混算。

## 收尾检查 {#next}

每次交付角度数据前，至少做三件事：在字段名中写单位；用 0°、90°、180° 做锚点复核；把计算精度与展示精度分开。完成后再把结果送入三角函数、测量报告或动画系统。
