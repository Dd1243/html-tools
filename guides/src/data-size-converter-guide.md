## 先分清 bit、Byte 和单位体系 {#lead}

文件大小和网络速度经常被写成相似的字母，实际含义可能差 8 倍甚至更多。小写 `b` 通常表示 bit（比特），大写 `B` 表示 Byte（字节），`1 B = 8 bit`。宽带套餐里的 `100 Mbps` 是每秒 100 兆比特，下载器显示的 `MB/s` 是每秒兆字节，理论上前者除以 8 才能比较。使用[数据大小换算器](../tools/converter/data-size-converter.html)前，先确认输入是存储容量还是传输速率。

第二个区别是十进制和二进制。厂商常用 `1 kB = 1,000 B`、`1 MB = 1,000,000 B`；操作系统和开发工具有时使用 `1 KiB = 1,024 B`、`1 MiB = 1,048,576 B`。严格写法中，`kB/MB/GB` 是十进制，`KiB/MiB/GiB` 是二进制。很多界面仍把二进制数显示成 KB，造成“标称容量比系统容量大”的错觉。

## 单位速查与换算关系 {#units}

| 单位 | 含义 | 常见换算 |
| --- | --- | --- |
| bit（b） | 比特，网络传输的基本单位 | `8 bit = 1 Byte` |
| Byte（B） | 字节，文件和内存常见单位 | `1 B = 8 bit` |
| kB、MB、GB | 十进制容量 | 每级乘 `1,000` |
| KiB、MiB、GiB | 二进制容量 | 每级乘 `1,024` |
| Mbps、Gbps | 每秒兆/吉比特 | 通常用于带宽 |
| MB/s、GB/s | 每秒兆/吉字节 | 通常用于下载和磁盘速度 |

`1 GB` 在十进制中是 `1,000,000,000 B`，约等于 `0.931 GiB`；`1 GiB` 是 `1,073,741,824 B`。同一个硬盘在包装上显示 `1 TB`，操作系统可能显示约 `931 GiB`，这不是容量被偷走，而是单位体系和格式化分区占用不同。查看结果时不要只比较数字，要把单位后缀一起读完。

## 使用数据大小换算器的步骤 {#steps}

1. 打开[数据大小换算器](../tools/converter/data-size-converter.html)，确认页面区分了 bit、Byte、十进制和二进制单位。
2. 选择原单位。例如宽带写 `Mbps`，文件写 `MB`，内存写 `GiB`；不要把速率单位当容量单位。
3. 选择目标单位，必要时先转换为 Byte 做中间基准，再转换到 `MiB` 或 `GB`。
4. 输入数值后，检查大小写和每秒符号。`50 MB/s` 与 `50 MB` 不是同一类数据。
5. 读取结果并用 `8` 倍关系做抽查。若把 `800 Mbps` 转成字节速率，理论上约为 `100 MB/s`，再扣除协议开销后实际下载速度可能略低。
6. 记录采用的体系。写文档时优先使用 `MiB`、`GiB` 等明确后缀；若产品界面写的是“GB”，在说明中注明它采用十进制还是二进制。

## 网速和下载时间怎么估算 {#network}

网络套餐按 bit/s 表示，下载客户端按 Byte/s 显示。理论下载速度公式是：

`字节每秒 = 比特每秒 ÷ 8`

例如 `200 Mbps` 的线路，理想值约为 `25 MB/s`。下载一个 `10 GB` 的文件时，按十进制容量计算，理想时间约为 `10,000 MB ÷ 25 MB/s = 400 秒`，也就是约 6 分 40 秒。实际还会受到 Wi-Fi 信号、服务器限速、TCP/QUIC 协议开销、并发连接和磁盘写入速度影响，预算时间应乘以 1.1 至 1.5 的安全系数，而不是把理想值当承诺。

上传速度和下载速度可能不同。对称光纤、移动网络和企业专线的上下行配置各不相同，测速网站还可能显示 bit 和 Byte 两种结果。若下载器显示 `12.5 MB/s`，对应约 `100 Mbps`，这并不代表套餐只有 12.5 Mbps。看不懂时先把所有结果转换到同一单位，再比较。

## 文件、内存与硬盘场景 {#storage}

文件管理器显示的大小可能是十进制或二进制，操作系统版本不同也会变化。压缩包的“大小”和“占用空间”不同：前者是文件内容长度，后者会按磁盘分配单元向上取整。一个只有几百字节的小文件，也可能占用 4 KiB 磁盘空间。清理磁盘时应看“占用空间”，传输和计费时通常看文件大小。

内存条标称 `16 GB` 多数按十进制或市场约定命名，系统监控可能显示约 `15.6 GiB`，还要扣除硬件保留和显存共享。云存储套餐的 `1 TB` 可能按十进制计费，数据库工具则按二进制显示。采购和容量规划时，把“厂商标称”“操作系统可用”“业务实际可用”分成三列，避免把三者混成一个数字。

备份预算还要考虑版本、快照和冗余。每天新增 `80 GB`，保留 30 天并不是简单的 `2,400 GB`；全量备份、增量链、压缩率、校验副本和对象存储最小计费单位都会改变结果。换算器只负责单位统一，容量模型应把每一项假设写出来。

在程序和接口中，建议把容量保存为整数 Byte，把展示单位放到前端格式化。这样可以避免 JavaScript 浮点数、数据库小数和不同语言的舍入规则造成累计误差。处理大于 `2^53` 的字节数时，要使用安全整数或高精度类型，不能把超大文件大小无条件塞进普通浮点变量。日志里记录原始 Byte 值、展示值和采用的单位体系，出现“系统显示少了几 GB”时才能快速判断是格式化问题、单位问题，还是实际数据丢失。

## 错误对照 {#errors}

| 现象 | 错误判断 | 正确处理 |
| --- | --- | --- |
| 宽带 100 Mbps 下载 12.5 MB/s | 认为速度只有 12.5 Mbps | 先除以 8，单位已经从 bit 变成 Byte |
| 1 GB 与 1 GiB | 当作完全相等 | 十进制与二进制基数分别为 1,000 和 1,024 |
| 小写 b 和大写 B | 忽略大小写 | `b` 是 bit，`B` 是 Byte |
| 文件大小与占用空间 | 认为两者必须一致 | 分配单元、压缩和文件系统会造成差异 |
| 下载时间 | 用理论峰值承诺完成时间 | 加入网络、服务器和磁盘开销 |
| 容量后缀 | 只保留数字不保留单位 | 结果必须连同体系和每秒标记记录 |

一个常见反例是“手机套餐 1 GB 流量等于下载 1 GB 文件”。如果套餐按十进制计费，而文件工具按二进制显示，数字会有差异；此外网页请求、协议头、图片和后台同步也会消耗流量。预算流量时应增加余量，不能把文件压缩后的大小当作全部网络开销。

## 真实场景：选择硬盘与规划备份 {#scenarios}

团队需要保存 2 年的日志，每天原始日志 `18 GB`，压缩后约为原来的 35%，每周保留一个全量快照，另有一份异地副本。第一步把所有容量统一为十进制 GB，第二步分别计算热存储、快照和异地副本，第三步再换算为云厂商的 TiB 计费单位。若直接把 `18` 当作 `18 GiB`，并把压缩率应用到快照副本，预算会明显偏低。

家庭购买标称 `2 TB` 的硬盘，系统显示约 `1.81 TiB`。先解释十进制和二进制差异，再检查分区表、恢复分区和文件系统占用。若可用空间远低于这一范围，才需要进一步检查分区或硬盘健康，而不是立刻认为硬盘容量不足。

开发者发布安装包时，下载页可同时写“文件大小 84 MB”和“预计下载流量约 90 MB”。前者是静态文件，后者包含 HTTP 头、重试和校验请求。把两个数字分开说明，用户就不会因为浏览器显示略高而误以为文件被篡改。

## 何时使用相关工具 {#tool-choice}

主工具适合在 bit、Byte、十进制和二进制容量之间做清晰换算；若你在旧版计算器入口工作，可以用[存储换算器](../tools/calculator/storage-converter.html)交叉核对。页面若只显示“大小”而没有体系说明，可查看[数据大小工具](../tools/converter/data-size.html)或产品文档补充定义。涉及硬盘、对象存储和备份费用时，最终以供应商的计费单位为准。

排查容量异常时可以按三层检查：先确认单位和 bit/Byte 方向，再确认十进制或二进制体系，最后检查压缩、快照、分区和文件系统占用。比如上传一个 `4.8 GiB` 的备份，平台按十进制 GB 计费时，账单显示约 `5.154 GB` 并不奇怪；若同时存在请求费和出站费，还要把流量和存储拆开核算。容量报表中加入“原始字节数”列，通常比在末尾写一个模糊的“约 5G”更可靠。

做容量规划时，建议把峰值、平均值和增长率分开。日志每天平均新增 `18 GB`，但发布日可能短时产生 5 倍峰值；如果只按平均值购买磁盘，写满时会触发丢日志或服务降级。把容量换算与时间轴结合，按月模拟剩余空间，并设置 70% 和 85% 的预警线，比到 99% 才扩容更稳妥。

还要区分“可用容量”和“逻辑容量”。数据库压缩、去重和稀疏文件会让逻辑大小大于实际占用，快照删除也可能因为共享块仍被引用而没有立刻释放空间。看到工具计算出理论总量后，应回到存储系统查看实际使用、回收延迟和副本数，不能只用一个换算结果判断是否可以删除备份。

## 常见问题 {#faq}

### 为什么 `100 Mbps` 不是每秒下载 100 MB？

因为 `Mbps` 的小写 `b` 表示 bit，`MB` 的大写 `B` 表示 Byte。8 bit 才是 1 Byte，所以理论上 `100 Mbps ÷ 8 ≈ 12.5 MB/s`，实际还会扣除协议和环境开销。

### KB 和 KiB 哪个更大？

`1 KB` 通常指 1,000 字节，`1 KiB` 是 1,024 字节，因此同样写作“1”的情况下，KiB 更大。严格文档应使用明确的 `kB`、`KiB` 后缀。

### 硬盘标称容量为什么比系统显示的大？

厂商常用十进制 TB，系统可能按二进制 TiB 显示，还会扣除分区和文件系统元数据。统一单位后通常可以解释大部分差异。

### 计算下载时间要不要把 8 倍再算一次？

只有在速率和文件大小单位不同的时候需要换算。先把速率换成 Byte/s，再用文件的 Byte 数除以速率；若两者已经同为 MB 和 MB/s，就不要重复除以 8。

### 数据大小换算器能预测云存储账单吗？

不能单独预测。账单还受请求次数、最小计费时长、快照、出站流量、冗余和税费影响。换算器只能提供容量和速率的统一口径。
