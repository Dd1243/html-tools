如何使用端口扫描演示

  1. 输入端口号或选择预设，例如 22,80,443,8000-8003。工具会去重、升序排列，并提示无效端口或过大的范围。
  2. 选择 Web、数据库或防火墙样例，点击“运行扫描演示”。每个场景按固定规则显示状态，其他端口不会被随机判定为开放。
  3. 按端口、服务、分类或状态筛选，复制当前可见行或导出 CSV。报告带有“演示数据”标记，便于与真实扫描报告区分。

常用端口查询能告诉你什么？

TCP 22 常用于 SSH，80 与 443 常用于 HTTP 与 HTTPS，3306 常用于 MySQL，5432 常用于 PostgreSQL，6379 常用于 Redis。端口号只是服务线索；更换配置后，同一服务可以使用不同端口。本页列出的是常见用途，不能据此判断服务版本或漏洞。

需要检查自己的服务器？

在你有权限管理的主机上，可使用 Nmap 执行真实 TCP 连接扫描。例如：

nmap -sT -p 22,80,443 example.com

将示例域名替换成你的目标，再结合服务器监听地址、防火墙、安全组和实际扫描位置解读结果。该命令需要本地安装 Nmap；网页不会执行它。

参考实现：Portchecker.io 采用后端 API 检测 TCP 端口；Nmap 端口状态说明解释了真实扫描中不同状态的含义。

读懂三种示例状态

开放 Open
真实 TCP 扫描中表示存在应用监听并接受连接。本页只展示样例，不验证监听状态。
关闭 Closed
真实扫描中常表示目标可达，但该端口没有应用监听。本页 Web 场景将 80、443 之外的端口预设为关闭。
被过滤 Filtered
真实扫描中表示探测无法确认端口是否开放，可能受防火墙等影响。本页防火墙场景将 443 之外的端口预设为被过滤。

关于在线端口扫描器的常见问题

这个页面会扫描我输入的 IP 吗？

不会。页面只接收端口列表，不接收目标 IP，也不发送扫描请求。所有状态来自明确标注的样例场景，不能用于判断真实服务器是否可达。

为什么不直接在浏览器里扫描 TCP 或 UDP？

普通网页没有通用的原生 TCP/UDP socket 扫描能力。用 HTTP 请求或 WebSocket 推断端口状态会受到跨域、协议、TLS 和浏览器限制影响，失败不等于端口关闭。真实扫描需要合适的本地程序或后端服务。

53 端口为什么只显示 TCP？

DNS 可以使用 UDP，也可以使用 TCP。本页演示范围统一为 TCP，列出 53 并不意味着 DNS 仅使用 TCP，也没有执行 UDP 检测。

能离线使用和保存结果吗？

可以。保存此 HTML 文件后，用浏览器打开即可运行端口查询、扫描演示和 CSV 导出。复制功能会优先使用浏览器剪贴板，受限时会显示可手动选择的报告。广告和站点导航需要联网，核心工具逻辑没有外部依赖。
