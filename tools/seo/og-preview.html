    怎样用真实源码检查分享卡片

    分享卡片的标题、描述和封面通常来自页面里的元数据。浏览器地址栏能够打开网页，并不表示分享平台一定能读取到同一份内容：登录状态、服务器跳转、机器人访问规则、页面脚本和平台缓存，都可能改变抓取结果。本工具从你提供的 HTML 开始检查，能回答“这份源码实际声明了什么”，但无法代替 Facebook、X 或 LinkedIn 的服务器访问。因此，卡片旁始终标注为示意，不把一个看起来完整的预览当作发布成功的证明。

    先确定你检查的是哪一份 HTML

    粘贴浏览器的网页源代码，或把构建产物保存为 UTF-8 HTML 文件后导入，然后点击解析。完整文档只检查 head 直属的相关标签；单独片段只检查顶层标签，正文中的同名文字不会自动成为元数据。模板、脚本、样式、noscript 和外来命名空间中的内容不参与提取。导入过程不会执行脚本，也不会把页面图片、样式或嵌入框架接入当前文档。页面修改后，报告立即清空，重新解析才会产生新结果，避免拿旧报告判断新源码。

    页面 URL 输入框是相对地址的解析基准，并不是抓取入口。填写一个网址不会下载该网页，也不会替你生成 og:url。若源码包含 base href，本工具采用第一个带 href 的 base 元素，保留原文并记录有效基准。相对 base 需要页面 URL 才能换算，绝对 HTTP(S) base 可以单独使用。首个 base 无效时会明确提醒，不会悄悄改用后面的 base；仍应查看发布页面实际的 head，确认构建工具是否注入了另一套地址。

    先看原始标签，再看回退后的示意

    Open Graph 的四项基础属性是 og:title、og:type、og:image 和 og:url。这里只要缺少非空值就会提示，即使普通 title 可以帮助绘制标题，也不会消除缺少 og:title 的问题。OG 标题或描述标签完全不存在时，预演可以使用 HTML title 或 description，并在来源说明里标出；标签已经存在却为空时，空值保留，不用后面的重复值掩盖问题。排查时应从原始标签表向下看，确认到底是哪一个构建插件或主题先输出了错误标签。

    X 有单独的 twitter:title、twitter:description 和 twitter:image 覆盖字段。本工具在这些字段不存在时回退到原始 OG 对应字段，并标明来源，不把普通 HTML 标题再次当成 X 的保证回退。twitter:card 未声明时显示“未声明”，只提供带说明的摘要示意；summary 与 summary_large_image 的图片布局不同。player 和 app 需要额外的平台能力，本工具不会伪装成已经完整支持。对于重复 X 字段，首项仅是本工具便于定位问题的检查规则，不能据此推断平台一定采用相同优先级。

    多张封面为什么必须分组检查

    一个页面可以声明多张 og:image，og:image:url 也是图片根字段。每次出现根字段，就建立一个新的图片组；紧随其后的 secure_url、type、width、height 和 alt 归属于最近的一组。把第二张图片的替代文本写在第一张图片后面，会让这些信息绑定错位。没有前置图片根字段的结构属性会单独提示，重复的同组属性保留原始记录并采用第一项。检查分组比仅仅数一数有多少个 image 标签更能帮助找到分享封面不符的原因。

    预演下拉框可以查看另一张 OG 图片，但不会改变报告里的源序首选。Facebook 和 LinkedIn 的示意跟随这项选择；X 始终按自己的图片字段与回退来源展示。有效 HTTPS secure_url 可以作为同组根图片的安全地址，空值或不安全根地址仍保留问题。宽高声明只是源码中的数字，不能证明远程文件真实尺寸；本地图片会实际解码后检查尺寸。替代文本应描述画面内容，而不是重复堆砌标题或关键词。

    图片加载、隐私与离线使用

    解析 HTML 本身不会请求标签里的图片。只有点击“加载远程图片”，当前选中的安全 HTTP(S) 地址才会通过图片请求加载，并设置不发送引用来源。图片服务仍会接收到网络请求以及通常的连接信息；离线、鉴权、防盗链、格式错误或服务器拒绝都可能导致加载失败。这种失败只说明当前浏览器没有加载成功，不能直接推断分享平台也一定失败。本工具不绕过服务端权限，也不通过公共代理抓取网页。

    你也可以选择本地 PNG、JPEG、WebP 或 GIF 看裁切与文字位置。文件只在浏览器中读取，工具检查文件签名、解码结果、大小和像素上限，不只相信后缀名或上传类型。SVG 不在本地图支持范围。图片只用于预演，不会把 blob 地址、文件内容或示例封面写入 JSON；报告仍描述源标签声明的图片。内置示例的封面是在本地绘制的虚构素材，不需要请求示例域名。广告与同意管理资源仍按站点配置运行，核心解析功能可以离线使用。

    发布后怎样继续排查

    当标签检查无误而真实分享仍显示旧内容时，先确认服务器返回的 HTML 已经更新，再查看最终 URL、跳转链、公开访问权限和图片是否可独立打开。之后使用对应平台提供的检查入口了解其抓取与缓存情况。平台可能调整布局、裁切、摘要选择或缓存策略，本工具不写死“等多少分钟必定更新”之类保证。把重要文字放在图片中间安全区域、让标题在窄屏仍容易理解，比只对齐某个示意框的像素更稳妥。

    JSON 报告适合交给负责主题、构建模板或内容发布的同事：它保留每条标签的原始值、解析地址、图片结构、回退来源与检查提示，方便比较修改前后。它不包含整页 HTML，也不代表目标网页已经通过平台审核。复制被浏览器权限阻止时，页面会选中报告文本，供你手动复制；下载则在本地生成 JSON 文件。切换 HTML 与手动模式时，两边内容独立，清空只作用于当前模式。

    协议与平台说明可参考 Open Graph protocol 、 X 开发者文档 及 Meta Sharing Debugger 。平台页面与功能可能变化，请以其当前实际说明为准。
