怎样用链接清单检查网页

链接分析适合文章发布、导航改版、CMS 模板调整和静态网页交付。先确认入口指向哪里，再检查链接名称是否清楚、属性是否符合使用场景。本工具读取你提供的 HTML，整理 a 和 area 元素、解析地址、提取静态名称，并把需要核对的位置列成报告。全部分析在浏览器内完成，不上传源码，也不访问提取出的目标网址。

从源码到可交付报告

  1. 粘贴 HTML，或导入本地 UTF-8 编码的 HTML、HTM、TXT 文件。填写这份源码原本所在的完整页面网址，例如 https://example.com/docs/page.html；只有域名而没有原页面路径，可能改变相对地址的解析结果。
  2. 确认分析语境和范围。检查完整页面可包含导航、正文和页脚；只看 main 或 article 时，应留意目标锚点可能位于范围外。对于截取的 HTML 片段，不要把未包含的内容直接判断为线上缺失。
  3. 查看解析基址、内外链分类及检查项。通过地址、名称、类型或 rel 筛选找到相关记录；重复目标仍保留每次出现，便于比较导航和正文中的不同文案。
  4. 核对具体链接后导出 CSV 或 JSON，也可复制唯一 HTTP(S) 网址清单。列表筛选和分页用于阅读，完整导出保留本次输入范围内的全部记录。

相对地址、base 标签与内外链口径

相对地址没有独立的站点信息。例如 ../guide 相对于 /docs/page.html 与相对于站点首页，得到的路径并不相同。工具优先读取源码中的首个 base[href] 作为解析线索；base 自身是相对地址时，仍需要页面网址。页面网址为空时，无法解析的相对链接会显示待解析，已经完整的 HTTP(S) 地址也不会被随意指定为某个站点的内链。

解析基址与页面归属是两件事。源码中的 base 可以指向资源域名，它改变相对 href 的目标，却不会把原页面变成资源域名所属的页面。即使 href 只是 #intro，也可能因为 base 指向别处而成为其他文档的链接。因此应先看解析后的目标，再判断是否为当前页面的锚点。

默认同源口径比较协议、主机名和端口。同主机口径则只比较主机名，忽略协议和端口差异；两种口径都不会自动把不同子域归成同一站点。例如 docs.example.com 与 example.com 会分别统计。报告给出的是明确的分类规则，没有适用于所有网站的理想内外链比例。

链接文字与静态名称怎样判断

链接文字应让读者能预期目标内容。“查看安装步骤”通常比孤立的“点击这里”更清楚，但短名称是否合适仍取决于相邻段落、按钮位置和页面上下文。图片链接可以使用 alt 提供入口名称；图像映射中的 area 也应检查其 alt。只有 href 而没有可理解名称的入口值得优先复核。

报告区分文字内容与按静态规则解析的名称。名称可能来自图片 alt、aria-label、aria-labelledby 引用或 title 回退；辅助技术使用的名称与搜索引擎理解的锚文本并非完全相同。本工具不执行完整无障碍名称算法，也不计算外部 CSS、生成内容或运行时更新。“未解析到名称”表示需要查看实际页面，不代表已经完成无障碍审计。

没有 href 的 a 元素可能是命名锚点或预留占位，本来就不是可导航的超链接。工具单独呈现这类元素，避免把书签误算成外链。空 href 则应核对用途：它可能重新导航到当前文档或基址，并不等于一个已经确认的 404。mailto、tel 和其他协议也分别显示，不混入普通网页内外链统计。

nofollow、sponsored、ugc 与新窗口

普通编辑链接不必统一添加 rel。付费推广或商业合作链接通常使用 sponsored，评论等用户提交内容可使用 ugc；nofollow 适用于需要限定关联的其他情况。它们是搜索引擎处理链接时的线索，不能保证目标页面不会通过其他链接或途径被发现，也不能用于推算一条链接传递了多少权重。

工具以完整词项识别这些 SEO 值，并兼容 Google 文档允许的空格或逗号分隔写法；notnofollow 不会被误认成 nofollow。浏览器安全属性仍按 HTML 的空白分词规则处理，两者不能混为一谈。现代浏览器中 target="_blank" 通常已经隐含 noopener，因此未显式写 noopener 不能直接判定为安全漏洞。是否打开新窗口也应由使用场景决定。

页内目标与静态分析的边界

只有解析后仍指向当前文档的链接，才适合核对本次输入里的 id 或传统 a[name]。判断当前文档时保留查询参数，因此 ?lang=en#intro 可能指向另一份页面内容。片段中的百分号编码会尝试解码，+ 保留为加号；空片段、回到顶部的特殊写法和文本片段指令则不按普通缺失 ID 处理。

“未在输入中找到目标”与线上链接不可用有不同含义。目标可能由脚本生成，可能在未复制的区域，也可能确实被编辑删除。工具不会请求 HTTP 状态、跟随重定向或检查登录权限；确认 200、404、超时及跳转链需要另行使用网络检测工具。对于动态网页，可在目标浏览器中导出渲染后的 HTML 后再检查。

常见问题

同一个网址出现多次，是否应该删掉？

未必。导航、正文推荐和页脚可能需要指向相同页面。工具保留各次出现的文字与 rel，并提供唯一网址统计。重复目标只是整理线索，应结合入口是否有用判断，而不是按次数扣分。

为什么填写页面网址后，分类发生了变化？

页面网址提供相对地址的解析上下文，也提供内外链的比较参照。请填写源码原来的页面地址，并检查 base 标签是否改变了解析基址。修改网址或选项后需要使用新生成的报告。

CSV 与 JSON 导出有哪些区别？

CSV 适合在表格软件中筛选和交付；为避免源码文本被当成公式，可能在公式式内容前增加单引号。JSON 保留结构及原始字段，适合程序处理。两种报告都可能包含内部网址与链接名称，分享前请按实际内容检查。

源码、文件或链接太多怎么办？

单个文件上限为 2 MB，源码上限为一百万字符，链接元素上限为五千个，解析后的名称累计上限为两百万字符。超限会停止并提示，不会截去后半段后继续给出正常结论。可以选择正文范围或拆分片段，再分别导出结果。

刷新后能恢复刚才的源码吗？

输入不会自动写入本地存储，也不会放进分享网址。刷新后需要重新粘贴或导入，请及时导出需要保留的报告。主题偏好可以单独保存；浏览器禁用存储或剪贴板时，核心分析仍可使用。
