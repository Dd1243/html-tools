只在你的浏览器内分析 内容不上传、不自动保存。核心功能可离线使用。

    怎样用标题大纲检查网页结构

    标题结构描述的是内容之间的关系。原生 H1 到 H6 表示六级标题，通常用 H1 概括页面主题，用 H2 划分主要章节，用 H3 继续展开子主题。它们应服务于内容组织，而不是只用来获得更大的字号。标题分析适合文章发布、CMS 模板调整、产品页改版和无障碍复核：先看大纲是否能独立讲清这页内容，再回到具体段落确认标题与内容相符。

    本工具读取你提供的静态 HTML，不抓取网址，也不运行其中的 JavaScript。它提取原生标题及可选的 ARIA 标题，按源码顺序建立父子关系，标出未解析到名称、无效 ARIA 层级与向下跳级的位置，并将需要上下文判断的事项单独列为人工建议。结果不是搜索引擎评分，也不能预测关键词排名。

    从源码到检查报告

    1. 粘贴完整页面、HTML 片段，或导入本地 UTF-8 编码的 HTML、HTM、TXT 文件。工具不会执行输入里的脚本，不会加载其中的图片、框架或样式资源。
    2. 选择“完整页面”或“HTML 片段”。全文模式会提醒你核对页面主标题，片段模式不会因为没有 H1 而要求补齐一个与上下文无关的主标题。
    3. 如果导航和侧栏干扰正文判断，可将范围切换到 main 或 article，也可填写 #content、.article-body 等 CSS 选择器。多个匹配区域按原文顺序合并，嵌套区域不会重复统计同一个标题；没有匹配时会明确提示，不生成看似正常的空报告。
    4. 查看大纲的父子层级与检查项。点击标题显示其标签、字符数与 ID；点击检查项中的序号会定位到对应的大纲条目。搜索和级别筛选只影响显示，下载报告始终保留本次范围内的全部标题。
    5. 将文本报告复制给协作者，或下载 TXT、JSON 留档。报告包含标题名称、ID、层级和建议，不包含整份原始 HTML。下载后可根据标题序号和 ID 回到编辑器定位原始元素。

    如何判断标题跳级

    从 H2 直接进入 H4，通常表示中间缺少一个组织层次，值得检查是否为样式效果而选错了标签。由 H4 回到 H2 则可能是在结束一个子章节、开始新的主要章节，是正常的返回上级行为。本工具只对向更深处跨过一级的情况发出提示，不会把所有级别变化都标为问题，也不会因为 section 或 article 容器就自动重置标题级别。

    首次出现的标题也需要结合语境判断。一个完整页面的导航标题可能先于正文 H1 出现，单独截取的文章片段也可能从 H2 或 H3 开始。若把全站页头、正文和页脚混在一起检查，合理的独立区域可能看起来像一次跳级。先限定正文范围，再审查章节关系，通常比逐个改标签更有帮助。

    多个 H1、重复标题和长度提示

    多个 H1 不等于搜索惩罚，也没有适用于所有页面的理想标题数量。对常见文章和详情页，保留一个明确的主题标题往往更容易理解和维护；对于结构复杂的页面，应先确认各区域的关系，而不是机械删除其他 H1。本工具将这一情况列为人工建议，不扣除虚构的 SEO 分数。

    重复名称可能来自多个独立模块，例如不同产品卡片下都出现“规格”。这不一定是错误，但阅读大纲时若无法区分它们，可以加入产品名称或场景限定。超过八十个字符的名称同样只是阅读提示线，并非 Google 的硬性限制。中文、英文与表情符号的视觉宽度也不相同，最终应以实际内容是否清楚、读屏导航是否易懂为准。

    ARIA 标题与静态名称检查

    原生标题能直接表达语义，通常优先使用。对于 role="heading" 的元素，aria-level 应提供正整数；ARIA 层级可以大于六，但这并不意味着 HTML 中存在 H7 标签。大纲会将这类元素显示为“ARIA 7”等标记。若原生 H2 被有效 aria-level 覆盖，数量仍按 H2 标签统计，大纲同时显示原生标签与 ARIA 层级，提醒你核对辅助技术体验。

    标题不一定只有直接文字。工具会检查文字内容、图片 alt、aria-label、可静态解析的 aria-labelledby 引用，以及 title 回退。普通标题中的显式隐藏子元素不会被当作可用名称；被直接引用的隐藏标签可参与名称计算。复杂的无障碍名称算法、CSS 生成内容和脚本更新仍需要浏览器无障碍树验证，因此“未解析到名称”表示应人工核对的具体位置，不能替代完整无障碍审计。

    隐藏内容、动态页面与隐私边界

    “排除显式隐藏标题”根据 hidden、aria-hidden 以及内联 display:none、visibility:hidden 等线索判断。内联 visibility 采用最近的明确声明，后代的 visibility:visible 可以恢复可见性；祖先的 hidden、aria-hidden 或 display:none 则仍会排除该标题。它不计算外部样式表、媒体查询或布局，因此无法完整判断最终可见性。关闭此选项可以查看这些源码元素。template 中尚未实例化的内容、脚本里的 HTML 字符串以及 Shadow DOM 中没有出现在输入里的节点，也不属于当前大纲。

    对于 React、Vue 等依赖运行时生成内容的页面，服务器源码可能只有一个应用容器。此时应在目标浏览器中导出渲染后的目标区域，再粘贴分析；本工具本身仍不会运行该页面脚本。输入不自动保存在 localStorage，也不会编码到分享链接中。刷新后需要重新提供源码，请及时下载报告；报告仍包含你分析的标题名称，分享前应确认其中没有内部信息。

    常见问题

    标题数量多，SEO 就会更好吗？

    标题的作用是组织内容，没有通用的理想数量。简短通知可能不需要复杂分级，长文章则需要清晰章节。应由内容关系决定标签，而不是为了满足数量增加空标题、重复标题或关键词。

    为什么完整页面与片段的建议不同？

    完整页面通常需要明确主题，但片段的上级标题可能在截取范围外。片段模式仍检查名称和内部层级关系，只是不因缺少 H1 就要求补一个与所在页面冲突的主标题。将范围限定到正文后，也应据实际截取内容选择语境。

    为什么 html[lang] 这样的范围选择器没有匹配？

    为安全地保留 head、body 与正文结构，工具在不活动的文档中解析 HTML。输入中 html 根元素的属性不会被保留，因此 html[lang]、html#page 等依赖根属性的选择器不适用；根元素上的 hidden、ARIA 或内联样式也不参与隐藏判断。body 自身的 ID 和属性会保留；请按 body、main、article 或正文内容的 ID 选择范围。普通 HTML 片段也可直接分析。

    筛选后导出的报告会少掉其他标题吗？

    不会。文字搜索、级别与关联检查项筛选用于阅读大纲；导出始终来自当前输入及分析范围的完整结果。修改源码或范围后，旧结果会标为失效，复制和下载时重新分析，避免把旧报告当成新结果。

    文件读取失败或者 HTML 太大怎么办？

    单个文件上限为 2 MB，输入上限为一百万个字符，标题上限为两千个；重复 ARIA 引用造成解析后的标题名称合计超过两百万字符时也会停止。超限会明确报错，不会截掉后半段再给出正常结论。可导出正文区域或拆成多个片段检查。文件应使用 UTF-8 编码，其他编码可能导致文字异常。

    能直接输入网址扫描线上页面吗？

    当前版本只分析你提供的 HTML，不访问输入中的网址。可从浏览器查看源码、开发者工具或 CMS 导出后粘贴。浏览器加载网页、外部 CSS 和脚本得到的结果，与静态源码可能不同，请在发布流程中保留实际页面复核。
