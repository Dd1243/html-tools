NanoID 是什么，怎样选择合适的短 ID？

NanoID 是一种紧凑的随机标识符。默认从大小写字母、数字、下划线和连字符这 64 个字符中取样，生成 21 位 ID。本工具适合准备测试数据、命名文件和试验 ID 规则；实际系统应结合累计数据量与唯一索引处理重复。

三步生成并导出

  1. 选择标准、短 ID 或易读预设，再设置长度和每批数量。标准配置是 21 位，默认一次生成 10 个。
  2. 按业务选择字符集。如果使用自定义字符，工具会先去重，再按有效字符数计算随机熵；无效输入会在参数下方提示。
  3. 点击“生成 NanoID”。列表可逐条复制；TXT 是每行一个 ID；JSON 输出字符串数组，复制与下载均跟随所选格式。

修改参数不会覆盖上一批结果。结果区会提示参数已更改，重新生成后才会替换当前批次，方便你先复制已有内容。

长度和字符集一起决定随机空间

设有效字符数为 A、长度为 L，可选 ID 总数为 A 的 L 次方，随机熵为 L × log₂(A)。默认 64 字符、21 位的配置对应 126 bits；相同长度下，纯数字字符集的空间会小很多。

易读字符集排除了容易混淆的 0 O I l，适合人工抄写。纯数字的输出仍是字符串，可能以零开头，导入表格或数据库时应保留字符串类型，避免前导零丢失。

不要只根据“位数”判断是否够用。先确定字符集，再把预计累计生成量填入上方估算器。短邀请码还需结合有效期、限流、校验和重复重试来设计。

碰撞概率为什么与总量有关？

碰撞指两个独立生成的 ID 完全相同。两两比较的组合数会随累计生成量增长，因此不能把某个固定值当成所有业务的碰撞概率。

p ≈ 1 − exp(−n(n − 1) / (2 × Aᴸ))

这里 n 是累计生成量，A 是字符集大小，L 是长度。这是基于独立、均匀随机取样的生日问题近似。上方数值针对整个历史集合，不仅是当前页面的一批结果。

比如 10 位纯数字只有 10¹⁰ 种组合，累计生成十万个时，碰撞风险已经不可忽略。数据库主键应建立唯一约束，并在发生重复时重新生成。工具不会通过删除重复值来掩盖小空间的风险。

本地随机生成与使用边界

生成器使用浏览器的 crypto.getRandomValues()，并通过拒绝采样避免非二次幂字符集的取模偏差。缺少 Web Crypto 时会提示错误，不会回退到 Math.random()。

生成逻辑、样式和导出都在此 HTML 文件内，保存页面后可以离线使用。生成的 ID 与自定义字符集不会由工具发送到服务器；页面仍包含站点通用的同意管理与广告资源，其规则见隐私政策。

随机 ID 不是自动生效的权限校验，也不包含时间顺序。访问敏感资源仍需要鉴权。React 列表应使用数据中稳定的 ID，避免在每次渲染时重新生成 key。

常见问题

NanoID 绝对不会重复吗？

不能保证。独立随机生成存在非零碰撞概率，缩短长度、减少字符种类或增加累计生成量都会提高风险。数据库应使用唯一索引，插入冲突时重试；需要严格顺序或集中分配的业务，应选择相应的 ID 方案。

自定义字符集能包含中文、空格或特殊符号吗？

本工具只接受非空格的可见 ASCII 字符，自动去掉重复字符；去重后至少保留 2 种字符。中文、表情与空白会提示错误。可以使用引号、尖括号等可见符号，结果会按纯文本显示，但这类自定义 ID 用于 URL 时需要通过 encodeURIComponent 编码。

为什么修改长度后，结果还保留上一批？

参数统计与碰撞估算会即时更新，生成结果则保留到下一次点击生成。结果区会标明上一批的实际数量和长度，并提示当前参数已改变，避免把旧结果误认为新配置的输出。

复制失败或离线打开时应该怎么办？

浏览器可能限制剪贴板权限。工具会尝试备用复制方式；如果仍失败，会切换到可选中的文本框并提示手动复制。也可以直接下载 TXT 或 JSON。核心生成器不依赖第三方库，离线时也能生成和导出。

这些 ID 能直接用作密码或访问令牌吗？

不要把随机 ID 当成完整的认证方案。即使使用了加密随机源，令牌仍需结合足够的随机熵、过期时间、存储方式、权限校验和撤销机制。测试数据与实际敏感凭证也应分开管理。
