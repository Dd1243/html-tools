什么是 UUID 与 ULID？它们解决了什么问题？

在分布式系统和现代数据库设计中，生成全局唯一的标识符（ID）是一项核心任务。传统的自增整数 ID 虽然简单，但在分库分表、微服务架构以及需要隐藏内部数据量级的情况下，会面临主键冲突和安全风险。

UUID (Universally Unique Identifier) 是一套 128 位的标识符标准。最常用的 UUID v4 将版本和变体位之外的位用于随机数据。它不暴露生成时间，适合不需要按创建时间排序的 ID；随机标识符仍有理论碰撞概率，数据库应保留唯一约束。

UUID v7 和 ULID (Universally Unique Lexicographically Sortable Identifier) 都把毫秒时间戳放在 ID 的开头，按字节或字典序比较时通常能按生成时间排列。本工具会在同一页面实例、同一毫秒内递增随机字段，让本次生成的批量结果严格递增；不同设备、进程或时钟之间不保证严格顺序，索引写入收益也取决于数据库和工作负载。

不同 ID 类型的具体应用场景

  • UUID v4： 适用于不需要从 ID 中读取生成时间、也不依赖时间顺序的场景，例如分布式资源标识和文件名。随机 ID 不应替代访问控制令牌所需的独立安全设计。
  • UUID v7： 保持标准 UUID 格式并携带 48 位毫秒时间戳。需要兼容 UUID 类型且希望大致按时间排序时可以考虑；应结合数据库索引、隐私和迁移要求评估。
  • ULID： 用 26 个 Crockford Base32 字符表示 128 位信息，适合需要紧凑、可读和字典序排序的场景。它包含可解码的毫秒时间，公开时要考虑时间信息是否敏感。

如何使用本在线生成器？

  1. 选择类型： 根据业务选择 v4、v7 或 ULID，并确认目标数据库、消息系统或 API 对格式的兼容性。
  2. 设置格式： UUID 默认使用小写带连字符格式，也可转为大写或去除连字符；ULID 始终为 26 个字符，大小写由此项设置控制。
  3. 批量生成： 输入 1 到 1000 的整数后点击生成。批量结果按一行一个 ID 输出；超出范围或输入小数时会提示错误，不会改写输入值。
  4. 本地生成： ID 在浏览器中生成，不会提交到本工具的服务器。复制功能需要浏览器授权剪贴板；安全随机源不可用时，工具会停止生成而不退回到弱随机数。

常见问题解答 (FAQ)

1. UUID v7 会出现重复吗？

随机字段仍可能碰撞，所以 UUID v7 不是数学意义上的绝对唯一。本工具对同一页面实例内、同一毫秒生成的结果递增随机字段；其他页面、设备或进程之间没有共享状态。数据库应使用唯一索引并处理冲突。

2. 为什么 ULID 只有 26 位？

ULID 把 128 位编码成 26 个 Crockford Base32 字符。首字符只允许 0 到 7，以容纳编码填充位；字母表排除了 I、L、O、U，降低视觉混淆。ULID 会公开毫秒时间信息，设计接口时要考虑这一点。

3. 在数据库中使用 UUID 有什么弊端？

随机 v4 的插入位置可能分散，时间前缀 ID 通常更接近追加写入，但实际效果由数据库、索引和写入模式决定。UUID 与 ULID 占用空间通常也大于 64 位整数，需按字段类型和存储格式核算。
