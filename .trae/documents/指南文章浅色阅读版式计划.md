### 页面骨架（自上而下）

```
[sticky header: logo + 导航 · 使用指南 active]
main.page  width: min(1120px, 94%)
  breadcrumb

      .article-main

        #map   文档/工具对照表（可选小节）
        #what  …
        #when  …

        #errors …
        #checklist 检查清单（新增短节）
        #related …

        次卡：打开 JSON 格式化（右栏推广位，浅色版参考「推广推荐」）
```

### 必做组件

1. **核心一句话（`.key-takeaway`）**  
   - 标题：「核心一句话」  
   - 加粗结论，例如：`先格式化成可读结构，再谈改字段；不合法就别猜。`  
   - 副句 1 行灰色说明  
   - 浅底 + 左边 primary 竖条或 soft 边框

2. **右侧目录（`.toc-rail`）**  
   - 桌面：`grid-template-columns: minmax(0, 1fr) 240px`，**目录在右**  
   - 移动：目录上移到标题下或折叠为页内「目录」卡片（默认：小屏 TOC 在主栏上方，避免难找）  
   - sticky；条目 hover 用 primary-soft

3. **数据表（`.data-table`）**  
   至少 2 张：  
   - **格式化 vs 压缩 vs 校验**（动作 / 结果 / 何时用）  
   - **常见错误**（现象 / 原因 / 改法）——替代目前纯 h3+p 列表的一部分  

4. **示意框（`.callout` / `.code-panel`）**  
   - 好 JSON 一行 vs 格式化后多行（示意即可）  
   - 或「合法 / 非法」对照两框  
   - 浅灰底、等宽字体、圆角、细边框（浅色等价于参考站深色 code 块）

5. **对照表（`.doc-table`）**  
   - 列：入口 | 侧重  
   - 行：本文、JSON 格式化工具、JSON Diff、JSON↔YAML、指南列表  

6. **检查清单（`.checklist`）**  
   - 下单前式：粘贴前脱敏、先格式化、看报错位置、尾逗号/引号、再压缩等 5～7 条  

### 文案与 SEO

- **保留**：title、description、canonical、TechArticle / HowTo / BreadcrumbList / FAQPage  
- **阅读时长 pill**：改为「约 5 分钟」（与真实篇幅更一致）；HowTo `totalTime` 可改为 `PT5M`  
- **章节 id** 尽量稳定（`#what` 等），TOC 与旧锚点兼容；新增 `#tldr` `#checklist`  
- 正文不追求拉到 12 分钟；结构化优先，字数仍约 1500～2200

## Assumptions & Decisions

1. **方案 B 已确认**：浅色 token，不深色。  
2. **只深改单篇指南 + template**；列表页保持卡片 hub。  
3. **目录在右**；小屏 TOC 置于正文前。  
4. **内容重组不重写主题**：同一知识点，呈现改为表/框/结论。  
5. **无滚动 spy JS**（参考站也可无）；纯锚点即可。  
6. **不引入**共享 `article.css`。
