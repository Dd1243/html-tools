### 结构问题

- 版式已具备：全宽 hero、右 sticky TOC、`.key-takeaway`、`.data-table`、示意框雏形、checklist。
- **内容过薄**：多数章节只有表/列表一句，缺「是什么 / 为何 / 怎么做 / 踩坑」完整段落。
- **TOC 与正文脱节**：目录有 `#what` `#when` `#steps` `#errors` `#related` `#faq`，正文 section **多数无对应 id**（仅有 `#tldr`），且编号与标题不一致。
- 合法 JSON 示意框里 `pre` 缺开头 `{`（质量硬伤）。
- 若干 section 未包 `.card`，版式不统一。
- 样式缺 `.card` 正文段落/列表、`.code-panel`、小屏双栏示意等，长文可读性不足。

## 质量要求（验收标准，执行时必须满足）

1. **字数**：article 可见正文汉字 **≥ 2500**（脚本复测）；不以重复口号、无信息列表凑字。
2. **信息密度**：每节至少回答「场景 → 做法 → 注意点」；错误节有「现象 / 原因 / 改法」。
3. **可操作**：步骤可对着 [JSON 格式化工具](https://essays4u.net/tools/dev/json-formatter) 完成；主工具与相关工具链真实存在。
4. **准确性**：区分 JSON 与 JS 对象字面量；尾逗号、单引号、注释、`undefined`/`NaN` 说明正确；示例语法合法。
5. **结构化组件保留并充实**  
   - 核心一句话卡  
   - ≥2 张表（动作对比 + 常见错误）  
   - ≥1 组前后示意（压缩一行 vs 格式化 / 合法 vs 非法）  
   - 检查清单 6～8 条（可执行）  
   - 相关入口对照表或卡片 + 简短「何时用谁」  
   - FAQ ≥4 条，答案各 ≥2 句  
6. **SEO**：保留 TechArticle / HowTo / FAQ / Breadcrumb；FAQ JSON-LD 与正文同步；`totalTime` 与阅读时长一致（如 `PT8M` 或 `PT10M`）。
7. **版式**：仍为浅色 indigo + 右 TOC；小屏 TOC 不永久挡正文；锚点与 TOC 一一对应。
